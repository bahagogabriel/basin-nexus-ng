# Basin Nexus NG — User Experience Review and Improvement Roadmap

Date: 21 October 2026
Status: First-pass audit, not a certification or user research study.

## Review principles
The public atlas must support public users who may not know catchment nomenclature or GIS concepts. It should work well in desktop browsers and on touch tablets, make meaningful geographic layers easy to discover, and clearly distinguish stakeholder reports, provisional scientific modelling and verified locations.

## Review of current interface and screenshots
1. **Map is too constrained in normal view.** The three-panel desktop layout gives the map less than half the available horizontal space; expanded mode helps but is not self-evident to new visitors.
2. **Layer controls are crowded.** Border, states, LGAs, river mode, density, river visibility, lake visibility and labels compete in the map header and wrap into multiple rows at smaller widths. Proposed: grouped Layer Manager with three titled groups: Reference, Water, Labels; prominent catchment focus button.
3. **Legend overlays useful map space.** The upper-left legend covers features and has text that can be dense on tablets. Proposed: collapsible legend, automatically compact on mobile, with clear hydrology symbology and provenance toggle.
4. **Catchment selection and map navigation require education.** Currently a free-text search and scrolling directory. Proposed: explicit onboarding micro-guide (select catchment → view rivers/resources → inspect layers), clear Reset extent control, and visible active-catchment breadcrumb.
5. **Dense rivers need graduated scale.** All mapped reaches can be visually overwhelming at regional extent. Proposed: explicit Main/Tributaries/All hierarchy (already introduced) with performance checks, adaptive detail and a transparent legend indicating upstream drainage-area class rather than invented Strahler categories.
6. **LGA provenance and source information are technically sound but verbose in profile.** Proposed: summary-first profile sections (Geography, Water, People and Land, Risks, Interventions, Sources) with expandable methodology details.
7. **Keyboard and assistive accessibility.** The Canvas map is focusable but cannot expose each polygon/reach semantically. Directory controls provide partial navigation; thorough WCAG 2.2 AA contrast, touch-size, screen-reader and keyboard alternative checks are still required.
8. **Public communication and terminology.** Remove legacy 'boundary preview' wording where richer layers now exist, while retaining clear 'provisional' status and 'Northern Nigeria study footprint'. Avoid implying stakeholder datasets have already been verified or published.
9. **Phones/tablets and performance.** Browser gestures have passed simulated touch, but continue QA for non-drifting frames, memory bounds, failed network retries, and device orientation changes. Avoid eager-loading data for all catchments.
10. **Evidence discovery architecture.** Long-term homepage should offer search by catchment, state, LGA, resource theme and data status; profiles must link mapped assets to provenance and uncertainty, without publishing private attendance/signature records.

## Suggested UX milestones
**UX-A — Information architecture and navigation:** group map controls, consistent headings, search/autocomplete, breadcrumbs, explicit selected catchment, source-status labels.

**UX-B — Cartographic legibility and accessibility:** layer symbology, responsive/collapsible legend, adaptive river density, high-contrast design, keyboard-accessible alternatives and text equivalents.

**UX-C — Information discovery and profiles:** standardized catchment profile tabs, thematic resource explorer, downloads, data source receipts and traceable verification status.

**UX-D — Formal QA:** desktop 1280/1440/1920, tablet 800–1200, Android touch, phone 360/390/430; automated accessibility audits (axe), screenshot regression, performance profiling and selected user walkthroughs.

This audit is a planning record only; each milestone requires implementation, browser QA and successful GitHub Pages release. No source geometries, accepted overlay calculations or stakeholder record restrictions should change during cosmetic/UI-only revisions.

## UX-A implementation (v1.4; awaiting final browser acceptance)

The first interface revision groups secondary map controls in a Layers menu (water, administrative boundaries and labels), keeps river scope and density controls immediately accessible, introduces an explicit Focus catchment action, widens the map at desktop sizes, makes the legend collapsible and places the map at full width on tablet screens. All original GIS and calculated data are retained; the initial visual river preference is Main + tributaries (users can still show all reaches). The new release must pass Python publication gates and multi-viewport Chromium QA before being regarded as accepted.
